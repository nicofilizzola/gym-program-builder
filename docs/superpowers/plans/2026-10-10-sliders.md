# Sliders for Numbers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the sets, rep range and goal number fields with styled native range sliders (one drag instead of click-and-type), with fixed limits that validation and import also enforce.

**Architecture:** One frozen `LIMITS` constant in `src/validate.js` drives both validation and the sliders' `min`/`max`/`step`. A pure `setRepBound` in `src/exercise.js` implements the two-thumb push rule. The UI has one slider component: a `.slider` wrapper with a track (`::before`), a `.slider-fill` span positioned from CSS variables `--from` and `--to` (0–1), and one or two transparent `<input type="range">` on top. `refresh()` writes every card slider's value, fill and value text from the session, so a push of the other thumb shows immediately.

**Tech Stack:** HTML, CSS, vanilla JS ES modules, `node:test` on Node 22. No dependencies, no build step.

**Spec:** `AGENTS.md`: requirements 2, 6 and 14, the domain model, **Session file format**, the implementation guidelines on validation, slider limits, `setRepBound` and native sliders, and the "Sliders for numbers" entry under "Decided".

## Global Constraints

- No runtime or dev dependencies; no library for sliders. Use native `<input type="range">` only.
- Limits: sets 1–10 step 1; reps 1–30 step 1; goals 0.5–30 step 0.5. The goal slider's range is 0–30, and 0 means no goal.
- Exact messages:
  - Sets: `Sets must be a whole number from 1 to 10.`
  - Reps: `Reps must be whole numbers from 1 to 30, with min ≤ max.`
  - Goal: `Goal must be a multiple of 0.5 from 0.5 to 30.`
  - Import goal: `Goal for <Muscle> must be a multiple of 0.5 from 0.5 to 30.`
- Value text: sets `3`; reps `8–12` (en dash) or `8` when min = max; goals `4.5` or `No goal`.
- Accessible names: `Sets`, `Reps min`, `Reps max`, `<Muscle> goal`. A goal slider at 0 has `aria-valuetext="No goal"`.
- Every `input` event applies to the session and calls `refresh()`; no release step.
- Defaults stay 3 sets, 8–12 reps. The file format keys, the volume rules, the body map and the volume list are unchanged.
- Visual: 6px track on `--surface-2`, filled part `--accent`, 22px `--accent` thumb with a 3px `--surface` ring, and a 44px-tall hit area. Focus-visible thumb: `0 0 0 2px var(--surface), 0 0 0 4px var(--accent)` (the design system's 2px ring with a 2px offset). Value text uses the display font with `tabular-nums`.
- Rows and cards are built once (`renderExercises`, `renderGoalFields`) and updated in `refresh()` / `syncGoalFields()`, so focus and an active drag survive edits.

## Review Focus

1. **Two thumbs at the same value at the end of the track** (reps 30–30 from an import, or dragged there): the thumb on top can be dragged left, and doing so lowers both values. The last-touched input is on top (`.is-top`). Check by hand in Task 2.
2. **Two thumbs meeting mid-track** (8–8): dragging either way works. With keyboard focus on `Reps min`, pressing ↑ pushes max (8–8 → 9–9). The pure rule is tested in Task 1; check by hand in Task 2.
3. **Dragging a slider inside a card**: it must never start a card reorder, and the card's drag handle must still reorder. Check by hand in Task 2.
4. **A goal slider moved back to 0**: the goal is deleted from `session.goals` (not stored as 0). The row hides if its volume is 0, the readout drops the goal, and an exported file has no key for it. Check by hand in Task 3.
5. **Phone width (≤ 760px, e.g. 360px)**: the sliders fit the card and dialog with no horizontal scroll, every thumb stays reachable at both ends, and "Done" stays on screen. Check by hand in Tasks 2 and 3.

- [ ] **Step 3: Slider CSS**

- Remove the `.numbers` rules, including the mobile one. Add `.slider-field` (flex column, `gap: 6px`) and `.slider-head` (flex, `justify-content: space-between`, label style like `.field`: 0.875rem, 500, `--muted`). `.slider-value` uses `--text`, `--font-display`, 700, `tabular-nums`.
- `.slider`: `position: relative; height: 44px; --thumb: 22px`.
  - The track is `.slider::before`: absolute, vertically centred, `height: 6px`, `left`/`right` = `calc(var(--thumb) / 2)`, `--surface-2`, radius 999px.
  - `.slider-fill`: absolute, centred, 6px, `--accent`, radius 999px, `left: calc(var(--thumb) / 2 + (100% - var(--thumb)) * var(--from))`, `width: calc((100% - var(--thumb)) * (var(--to) - var(--from)))`. This matches the native thumb travel, so the fill ends under the thumb's centre.
- Range inputs: `position: absolute; inset: 0; width: 100%; height: 100%; margin: 0; appearance: none; background: transparent`. Give the WebKit and Firefox tracks (`::-webkit-slider-runnable-track`, `::-moz-range-track`) a transparent background and full height.
- Thumbs (`::-webkit-slider-thumb`, `::-moz-range-thumb`): 22px circle, `--accent`, `border: 3px solid var(--surface)`, `cursor: grab`. Hover: `box-shadow: 0 0 0 6px var(--accent-soft)`. Focus-visible: the ring from Global Constraints.
- In `.slider.is-range`, inputs get `pointer-events: none` and their thumbs `pointer-events: auto`. `.is-top` gets `z-index: 2`.
- Single sliders keep pointer events on the whole input, so a click on the track jumps there.
