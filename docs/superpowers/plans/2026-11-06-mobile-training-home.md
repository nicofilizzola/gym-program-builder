# Mobile Training Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or, if the user selects delegation, superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not begin implementation until the user reviews this plan and selects an execution method.

**Goal:** Make an immersive training home the mobile entry point, with one-tap recommended workout starts, offline Resume and a centered Home tab.

**Architecture:** Reuse the existing pure recommendation algorithm, start sheet and workout controller. Add a small Home controller/view pair, shared cover metadata and read-only workout observation. Persist cover identity in existing template/log JSON; preserve desktop navigation and existing workout ownership/sync.

**Tech Stack:** JavaScript ES modules, native DOM/CSS, Node 24, existing libSQL repositories, node:test and Playwright; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-mobile-training-home-design.md`. Read it with this plan; the user's request for this plan approves the written spec.

## Global Constraints

- Mobile breakpoint: **760px and below**. Mobile tabs: **Programs · Templates · Home · History · Catalog**. Desktop retains four tabs, its Workouts label and Programs default.
- Home is `#/home`; preserve `#/workouts`, workout deep links and explicit routes. No resize redirects or last-page persistence.
- **There is no history section on Home.** One cover, Start/Resume, Choose another workout, and necessary fallback/error actions only.
- Cover IDs: `gym`, `dumbbells`, `barbell`, `machines`; missing defaults to `gym`; invalid present values reject as `Invalid workout cover.`
- Portable bundles remain version 4; workout logs remain version 2; versions 1–4 of portable input and version 1/2 logs without covers remain readable. No SQL migration.
- Shared template owns the cover choice; new logs copy it as a snapshot. Cover metadata stays outside AI review, volume and analytics. No uploads or per-occurrence overrides.
- Resume uses the existing local mirror before recommendation requests settle. No new offline cold-launch, offline creation or PWA support.
- Reuse the existing first history page for suggestions; do not add all-history scheduling or change finish/discard semantics.
- Retain shell Profile, Log out, save status, safe areas and typing-state behavior. No duplicate header controls.
- Page gutter 12px, typical cover padding 20px, typical session title around 48px, primary action at least 54px tall, touch targets at least 44px; desktop Home max width 480px. Allow scrolling for small screens and enlarged text.
- Photo readability gradient only; 4.5:1 text contrast; no idle animation. Existing route/sheet motion; cover disclosure 200ms ease-out; reduced motion instant. Routine data/progress/image updates are instant.
- Deploy client and server validation together. Never claim a pending deployment was verified.

## Review Focus

- A response arriving after logout, replacement of the active workout or activation of another program must not resurrect an old cover or Start action (Tasks 3, 5, 8).
- A newly finished but unsynced workout must advance Home exactly once; a discarded or still-active workout must not count as completion (Tasks 2, 3, 5, 8).
- Existing mobile test login helpers must not hide desktop landing regressions or fail merely because Home replaces Programs (Task 8).
- Four shipped images must be reachable in development and build output without exposing arbitrary local files; image failure must leave Start/Resume readable (Tasks 6, 7).
- A focused button/radio and the bar's reserved space must survive acknowledgements, sheet closure, resize and rapid navigation without focus loss or phantom padding (Tasks 3, 6, 7, 8).
