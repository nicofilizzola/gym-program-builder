# Design system

The visual language of Gym Program Builder: a dark, athletic look with a single energetic orange accent. Everything here is implemented in plain CSS in `style.css` (tokens on `:root`) with no build step or UI library.

When you change a value, change it in `style.css` first and then update this file.

## Principles

- **One accent.** Orange (`--accent`) marks actions and selected state. Do not introduce a second accent colour. The only other colours are the four goal status colours (`--under`, `--met`, `--over`, `--no-goal`), reserved for the volume-list bars and the met checkmark (`--under` also marks profile limit hints), and the body map heat ramp (`--untrained`, `--heat-1` to `--heat-4`), reserved for the body map and its legend.
- **Volume is the hero.** Keep the body map and volume list prominent while editing: a sticky desktop rail when it fits, normal document flow when it exceeds the viewport, and the existing mobile panel placement.
- **Colour never stands alone.** Every body map colour is paired with the heat legend and the volume list's numbers (and the readout), the direct/indirect bar segments with the split as text (readout, row accessible name), every status colour with the `volume / goal` value, the met checkmark and the hidden status word, and every highlight with a text tag.
- **Simple over clever.** Hand-written CSS, inline SVG, no icon fonts, no emoji as icons.

## Feature design and review checklist

Use this checklist while designing, implementing and reviewing every UI change. Record decisions in the feature's existing spec/plan or short design note; a separate document is unnecessary. This is guidance for future changes, not a claim that every existing component already meets it.

- **Fit the existing screen.** Identify the nearest existing component and reuse its layout, spacing, typography and controls. Put related fields on aligned rows when space allows. Use disclosures for secondary settings. Avoid introducing a new card, heading or vertical section when an existing row or toolbar can hold the control. Let content wrap at narrow widths and enlarged text.
- **Choose icons with purpose.** Familiar repeated actions such as rename, archive, replace and remove should use the existing inline action-button pattern: currentColor SVG, accessible action-and-target name, shared hover/focus tooltip, and a direct action strip. Keep text on primary or unclear actions and preserve specifically required text buttons (including Import and Export; exercise, program workout and rest card Reorder use an icon). Tooltips supplement an accessible name; they never replace it. Preserve the established 32px fine-pointer desktop / 44px touch and hybrid targets, and 44px slider hit boxes.
- **Describe both states and the transition.** For every changed interaction, note the trigger, open/closed states, animated properties, duration/easing, reduced-motion fallback and focus destination. Choose the nearest existing motion pattern below. Explain any intentionally immediate reveal or dismissal. Live values, typing and save acknowledgements must remain immediate; decorative delays are inappropriate.
- **Inspect populated layouts.** Use the project's required desktop sizes (1366×768, 1440×900, 1920×1080), relevant mobile/tablet widths, 200% text and touch/hybrid input. Check long names, errors, wrapped action strips, visible focus rings, body figures and reachable content. Review useful density alongside readability and target sizes.
- **Play the interaction.** In a real browser, verify opening and closing, rapid toggles/reversal, Escape/outside dismissal where supported, keyboard focus and reduced motion. Check that neighbors move smoothly during disclosures and closing content cannot receive focus. Capture screenshots for layout evidence; verify motion through interaction. Report checks actually performed and any gaps in the completion note.

### Body map heatmap

The body map shows each muscle's absolute volume (direct + indirect), not its goal status, so its colours do not match the bars. One solid fill per muscle, with no direct/indirect split. The ramp builds to the accent orange at the ideal 4–6 sets and leans toward red above it. The pure function `heatLevel(volume)` in `src/volume.js` (unit-tested, limits in `HEAT_BANDS`) picks the level; CSS only maps a `data-heat` attribute to a token. Goals are ignored.

| Level | Volume | Token | Legend |
|---|---|---|---|
| 0 | 0 | `--untrained` | `0` |
| 1 | 0.5–3 | `--heat-1` | `1–3` |
| 2 | 3.5–6 | `--heat-2` | `4–6` |
| 3 | 6.5–9 | `--heat-3` | `7–9` |
| 4 | 9.5 and above | `--heat-4` | `10+` |

The legend (`#heat-key`, `aria-hidden`) sits centred under the two figures on every screen size: 0.75rem `--muted` labels, each after a 10px rounded swatch, like the Direct / Indirect key.

## Spacing, shape and elevation

- **Spacing:** 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32px. Cards stack with 16px gaps; fields inside a card are 12px apart.
- **Radius:** `--radius` 12px for cards and panel, 8px for inputs and buttons, 999px for chips, tags and bars.
- **Elevation:** flat by default. Shadows only for meaning: the primary-highlight glow on cards, and the upward shadow of the pinned mobile panel.

## Layout

- **Desktop (?1100px):** fluid canvas, 24px side gutters, 16px main gap, `minmax(0, 1fr) 460px`; the panel becomes 520px at ?1600px. Header, editor and program edges align. One compact application header carries product identity, labeled navigation and save/recovery controls. Page headings are 24px and names/actions use wrapping rows.
- **Tablet (761?1099px):** retain the previous 1120px cap and 340px session rail; program overview stacks at ?800px. Desktop density does not apply.
- **Mobile (≤ 760px):** one compact top row (save status left, Profile and Log out right) plus the [bottom tab bar](#mobile-tab-bar); single column (`minmax(0, 1fr)`, which prevents the chip row from causing horizontal scroll); the panel is pinned to the bottom with 120px-tall figures and the muscle list turned into one horizontally scrolling row of chips.

Compact library rows are normally 54px tall, with 8px between rows; long names and enlarged text grow naturally. Desktop exercise cards use 12px padding and 12px list gaps. Their main field row is name/sets/reps, and primary/secondary muscle fieldsets sit side by side when card content is at least 700px wide. Narrower cards put name above sets/reps and stack the fieldsets. All 13 muscle choices remain visible in both groups.

Programs retain one ordered list in sequence mode. Schedule (Week) mode is a single-column agenda at every width, Monday–Sunday then Unscheduled; see [Program review dock and Week agenda](#program-review-dock-and-week-agenda). Empty days retain 44px drop targets; workout cards grow naturally without internal scrollbars.

The program layout selector reads **Week / Sequence**, in that order. New programs open in Week; saved programs keep their applied layout. Sequence is headed **Sessions**, with an **Add rest day** action that appends a draggable, removable neutral rest card. Rest card actions are a right-aligned group (Reorder, Remove) on every viewport, matching workout cards. Rests use the existing surface/border/radius and 12px gaps; their inline padding always matches workout cards so both action groups share one right edge (12px 16px padding below 1100px, where workout cards use 16px; 8px 12px padding and 8px gaps from 1100px, where workout cards use 12px); they wrap and grow. Rests remain saved while hidden in Week and never affect weekday assignments or weekly volume.

Program session titles are native links to their occurrence editor, with a 150ms ease-out accent color and underline transition on hover/focus (instant under reduced motion). The Edit icon is removed; Duplicate and Remove remain visible icon buttons with accessible names and shared hover/focus tooltips. Title links preserve keyboard and modified-click navigation and never initiate dragging. Icon targets are 32px only on compact fine-pointer desktop without a coarse pointer, otherwise 44px. Workout and rest cards retain whole-card dragging and a visible Reorder icon action with movement options and a shared tooltip; rest cards also have a remove icon. Every program card icon uses the shared bordered `.action-button` (delete hover on Remove), whose pointer-aware sizing keeps icons centered in 32px and 44px targets. No separate session-card Move up/Move down buttons or day select are shown. Helper text explains touch holds and Reorder shortcuts: Up/Down reorder within the mixed Sequence or current day; Alt+Up/Down in Week move through the weekdays and Unscheduled, restoring Reorder focus and announcing the destination. Reorder menus include all weekday destinations, including empty days. Rest cards use the same grab/hold feedback and pointer-aware control targets as workout cards.

Week/Sequence switches fade only the session area: 75ms out, then 100ms in, ease-out, using the existing view-transition helper. The selector and weekly panel stay usable and steady; a newer selection cancels the old fade. Initial rendering and regular edits do not trigger this transition. Reduced motion switches instantly. Pending fades are canceled on list edits, editor navigation, server-driven updates and teardown.

## Components

### Shared session context

Program sessions resolve shared template data; session editing saves the template rather than the program arrangement. A muted Shared template link shares the editor heading in program context, wrapping naturally without an extra card; the breadcrumb provides the return navigation. The link uses 32px minimum height only at the established fine-pointer desktop breakpoint without any coarse pointer, otherwise 44px. Use the existing view fade for route entry/exit; do not add an entrance animation to the context row. Template and program names remain ordinary editable fields, and errors/recovery retain their existing surfaces. Acknowledgements update linked definitions without replacing focused controls or open variant drafts. Week/Sequence, body figures and volume layout stay unchanged.

Nested views now use a semantic Breadcrumb navigation above the existing heading instead of a redundant Back button. Trails follow program occurrence context and catalog reference/variant routes; root lists omit them. Breadcrumbs use the same canvas gutters (24px, 16px mobile), 1120px tablet and 1600px catalog caps, and fluid desktop editor width. Content below a trail uses 8px top padding to avoid stacking an extra header gap. Ancestors are native links, the current item uses aria-current, separators are decorative, and long names wrap. Touch/hybrid links remain 44px high, fine-pointer-only desktop links 32px. The Shared template link sits in the editor heading; names update live without an independent breadcrumb animation.

### Inputs
32px minimum height on fine-pointer desktop (?1100px), 44px elsewhere, `--surface-2` background, `--border` border. Focus: `--accent` border plus a 3px `--accent-soft` halo. Labels always visible above the field (never placeholder-only). Errors sit directly under the field they belong to.
Numbers (sets, rep range, goals) are never typed: they use sliders (below). Names use text inputs; optional program context uses qualitative multiline notes, not new numeric settings.

### Program context editor

The program header is one flex row (`header.program-heading`): the title, then `.program-identity` (program name field with the Week/Sequence selector 12px to its right, vertically centered on the name input). From 761px the identity is a grid, `minmax(12rem, 480px) max-content`: the name field spans the label and input rows as a subgrid and the selector sits in the input row with `align-items: center` (no offset margins), its two options never wrapping; below 761px the existing flex layout remains (options may stack). The identity's minimum is its content, so a narrow row moves the file actions to their own row instead of squeezing the name or selector, then `.program-file-actions` pushed to the right edge. The actions (Program context with a clipboard icon, Import, Export, AI review) stay one unbroken group with identical spacing with the review dock open or closed, moving to their own right-aligned row when needed; it never wraps internally at default text size on desktop; only when even a full row cannot fit (for example 200% text) does the group wrap internally, and labels are never clipped. The header itself wraps below the title row when narrow. Program reviews use the [review dock](#program-review-dock-and-week-agenda), headed AI review · Hypertrophy · AI-generated. At dock widths the dock stays open behind the context dialog; at full-screen review widths, opening context dismisses the review without discarding it or stopping generation. The report shows Program changed after relevant edits; template revision acknowledgements alone do not stale it. Validation messages use application-built occurrence links. Routine program/dependency updates patch the overview and preserve toolbar anchors, dialog fields, report nodes and focus; route navigation discards the temporary report.

The labeled Program context toolbar action opens a native modal at most 640px wide with 16px viewport clearance. Two optional, visibly labeled three-row textareas (Goals and priorities, Constraints and preferences) use the existing dark field treatment, Barlow and 12px field gaps. Short example guidance sits below each; no extra cards or required questionnaire. Notes apply live through the program autosave flow. Done stays reachable as a compact right-aligned action in a sticky footer with export helper text, wrapping when needed. Long prose wraps; short viewports/enlarged text scroll within the bounded dialog. Controls retain 32px fine-only desktop / 44px touch sizing.

Opening focuses Goals and priorities at the top of the editor; Done, Escape and backdrop dismiss without reverting and restore the toolbar trigger. Entry/exit use 180ms ease-out opacity and a 4px translation. A noninteractive top-layer exit surface preserves the closing picture and scroll position after native containment ends; stale callbacks cannot hide a rapidly reopened editor. Reduced motion settles immediately, including a changed preference mid-exit. Initial rendering and live input/acknowledgements do not animate. Refresh preserves the same textarea nodes, unchanged values, focus, selection and composition.

### Profile page

The app header holds a person-icon Profile action button (`#profile`, accessible name and shared tooltip `Profile`) immediately before Log out, with the same 32px fine-pointer desktop / 44px touch and hybrid sizing as other action buttons. On `#/profile` it carries `aria-current="page"` and the main-nav current treatment (accent icon, 10% accent tint, accent border). The `.profile-page` route shares the `.program-page` gutters and max width (`--canvas-gutter` from 1100px, 16px at ≤600px) and a compact 1.5rem desktop `h1` Profile.

**Sections.** Five plain headed groups (`.profile-section`, an `h2` at 1rem/600 with 8px below, 20px between sections; no cards, borders or backgrounds), in order: **Schedule** (Max training days per week slider, Available days pills, Max sessions per day radios), **Session length** (Max session length slider), **Experience** (Level radios, Typical reps in reserve slider), **Equipment** (equipment pills) and **Notes** (Training background and approach, Constraints and preferences). Fields sit in `.profile-fields`, a grid of two equal `minmax(0, 1fr)` columns from 761px (12px row / 24px column gaps, top-aligned) and one column below; the Equipment pill field spans both columns. Field labels and legends use the slider-head treatment (.875rem, 500, muted; .8125rem on compact desktops); helper text uses `.program-context-help` 4px below its control.

**Controls.** Sliders are the standard `.slider` (native range, 44px hit box, slider presentation) with the value readout on the label row; each leftmost position is a sentinel saved as `null` and read out as text in both the readout and `aria-valuetext`: max days 0–7 (`No limit`, then `1`…`7`), session length 15–180 by 5 (`No limit`, then `20 min`…`180 min`), reps in reserve −1–4 (`Not set`, then `0`…`4`); a null readout uses the muted `.is-empty` colour. Max sessions per day (`No limit / 1 / 2`) and Level (`Not set / Beginner (<1 yr) / Intermediate (1–3 yrs) / Advanced (3+ yrs)`) are native radios in a `fieldset`/`legend` drawn as `.segmented-control`, which shares the program Week/Sequence selector's rules, sized to its content (`fit-content`), wrapping options when the row is too narrow, with 44px minimum-width options (32px on compact desktops). Available days (`Mon`…`Sun`, accessible names `Monday`…`Sunday`) and Equipment (the equipment pill icons with visible labels) are `.toggle-pill` buttons with `aria-pressed` inside a labeled `role="group"`: a 999px pill in `--surface-2` with a `--border` outline and muted text, a lighter border and text on hover, and the `--accent-soft` fill, `--accent` border and `--text` colour when pressed, with the standard 2px accent focus ring; 44px tall and wide on touch and hybrid devices, 32px on compact fine-pointer desktops. Day pills use 4px padding and gaps with a 44px minimum width so all seven fit one 390px phone row. None pressed means not specified, as each group's helper text says. Both textareas are five rows in the program-context field treatment (2,000 UTF-16 code units) with their example guidance below; the note "Used by AI program reviews. Not included in program exports." closes the page (720px max width).

**Behaviour.** The view keeps a full local draft of all nine fields; every control change updates it and autosaves the whole normalized profile through the header save status (Retry on failure; a conflict offers Reload saved version only, which replaces every control). Saved acknowledgements only adopt fields the user has not changed since the last saved version and only touch controls whose value differs, so they never move focus or the caret, reset a dragged slider or undo another control's edit. Pill/radio colour changes use the chip's 150ms colour transition (none with reduced motion); routine data updates never animate. Route entry and exit use the existing view transition and focus the heading.

### Program review dock and Week agenda

Design: [program review dock spec](../superpowers/specs/2026-10-31-program-review-dock-design.md).

**Dock.** At viewport widths of 1024px and above, the program AI review is a docked right-hand column, not an overlay. The program route host (`.program-route`) is a two-column grid, `minmax(0, 1fr) 0px` while closed and `minmax(0, 1fr) var(--review-width)` while `.review-dock.is-open`, so the program content narrows to make room and regains the width on close. `--review-width` is 340px, or 360px at 1600px and above. The volume panel keeps its own width and the 180px/200px body figures. The dock spans the route's rows, uses `--surface`, a 1px `--border` left edge, no radius and no shadow. The route rows are `auto 1fr`, so any extra dock height goes below the program, never between the breadcrumbs and the header. The dock is `position: sticky; top: 0`; while open its height is `calc(100dvh - var(--review-dock-top, 0px))`, and once closed it returns to 0 after the 180ms exit so a closed dock never adds page height. JavaScript sets `--review-dock-top` to the route host's current viewport top (never below 0) on open, scroll (once per animation frame) and resize, so the dock fills the space below the app navigation and its footer stays reachable during normal page scrolling. From 1024px to 1279.98px the open dock leaves too little width for the side-by-side program grid, so `.program-route:has(> .review-dock.is-open) .program-grid` becomes a single column with the weekly panel first (`grid-row: 1`); this reflow is instant, not part of the 180ms column transition: it happens at the start of opening and at the end of closing. On close the dock keeps `.is-closing` (and the stack, via `.review-dock:is(.is-open, .is-closing)`) until the route's `grid-template-columns` transition ends (260ms fallback), so the sessions never squeeze into a narrow two-column layout mid-close; reopening cancels the hold, and with reduced motion the switch is immediate. Throughout, the panel keeps its full size and the 180px/200px body figures, and the side-by-side grid returns on close. Below 1024px (`max-width: 1023.98px`, matching the JavaScript query so fractional widths never fall between) the dock is `display: none` and the review opens as a full-screen native modal (`inset: 0`, `100dvh`, no radius, safe-area padding), with a 180ms ease-out opacity and 4px translation open/close; nodes survive exit and rapid reversal cancels old callbacks. Closing the modal transfers the same content into a nonmodal exit surface so native focus containment ends immediately.

**Shared review mechanics.** Barlow/dark/orange tokens stay authoritative, with a raised surface and editorial text sections; no chat bubbles, scores or new palette. Closing content becomes inert/`aria-hidden` immediately after focus restoration. The streaming indicator changes opacity only (no artificial typing or per-token entrance effects). Streaming follows only while the reader is within 48px of the report bottom; Jump to latest fades for 150ms without shifting controls; status announcements are separate from report text. Initial render never animates the review. Fine-pointer desktop targets are 32px, otherwise 44px.

**Structure and typography.** A fixed header (sparkle identity, "AI review" title, "Hypertrophy · AI-generated" caption, Close icon action; 12px 12px 8px padding, bottom border), an independently scrolling report region (0 12px 12px padding, the only new internal scroll area) holding the snapshot scope line (8px top padding), the status live region with the Program changed marker (8px 0 12px padding) and the report and a fixed footer (12px padding, top border) with Analyze again, Stop, Retry and Jump to latest as applicable. Review typography: title `600 1rem/1.4`, report `400 .875rem/1.45` with no larger lead paragraph, paragraphs `0 0 8px`, section headings `16px 0 6px` (no top margin on the first). Values are relative so enlarged text scales; report sections stay Assessment, Strengths, Improvements and Limits.

**Motion.** Opening and closing transition the route's `grid-template-columns`, the dock content's `transform` (`translateX(12px)` to none) and its `opacity`, each 180ms `ease-out`; the dock's `visibility` switches after 180ms when closing. Initial render and route entry never animate. Reopening during a close reverses smoothly. Reduced motion removes the route, dock and content transitions.

**Focus and Escape.** Opening moves focus to the review title. Close and Escape return focus to the AI review toggle; the dock becomes inert and `aria-hidden` immediately while its exit visual finishes, and keeps its DOM, report and scroll position for reopening. Escape closes the docked review only while focus is inside the dock, and never while another modal dialog is open; the full-screen modal closes on Escape anywhere. The dock is non-modal: the program stays editable and relevant edits mark the report Program changed. The Program context dialog opens over an open dock; at full-screen widths it dismisses the review first (report and generation retained). Crossing 1024px while open moves the same content between dock and modal, preserving report scroll and focus inside it. Closing and reopening, in either presentation and across the breakpoint, returns to the same report reading position (or the end while following a stream). The dock is a landmark labelled by the review title, and the toggle's `aria-controls` always names the surface the next open will use.

**AI review toggle.** A labeled `secondary-btn review-toggle` with an inline sparkle SVG (16px, `#ffc18e`), last in the program file actions with an 8px left margin on top of the 8px gap (16px from Export; the margin remains when the row wraps at 760px and below). Identity uses the accent family only: closed, a `#39271d`→`#25201c` fill with a `#edaa73`/`#ae622e`/`#795035` gradient border; open (`aria-expanded="true"`), a stronger `#62351c`→`#3b291e` fill with a brighter `#ffd0a6`/`#f29248`/`#bb743f` border and lighter text. Colour/shadow changes take 150ms `ease-out`. Under `(hover: hover) and (pointer: fine)`, each hover plays one 450ms `ease-out` light sweep (`ai-light-sweep`) across the button; touch never sweeps and keyboard focus shows the standard static 2px orange outline (3px offset). While a report generates (`is-generating`), only the sparkle breathes (`ai-sparkle-breathe`, opacity 1→.55 and scale 1→.92, 1600ms `ease-in-out` infinite). Idle buttons and initial render never animate. Reduced motion removes the sweep, breath and transitions while keeping the colours. Sizing follows the program file actions: 32px on fine-pointer desktops without a coarse pointer, otherwise 44px. When unavailable or still checking availability, the toggle is `aria-disabled`, dimmed to 65% opacity with a default cursor and no hover sweep, and explains "AI review is not configured yet." when pressed, in a right-aligned paragraph directly below the program header.

**Week agenda.** Week is always a single-column agenda (`.week-agenda`): one bordered row per weekday, Monday–Sunday, then Unscheduled (8px extra top margin), with 4px row padding. Each day row is an inline-size container: at 30rem and wider, the day label (`.8125rem`, 500, muted, sentence case, no letter spacing, 44px minimum height, wrapping inside its column if ever needed) floats in a 4.875rem column (6rem at viewport widths of 1600px and above) and the sessions sit 12px to its right; narrower day rows stack the label above the sessions. Session cards (6px 10px padding, 6px apart, 12px column gaps; name in the `1rem` body font, metadata `.8125rem` with 1.25 line height, a compact muscle badge with 1px 8px padding) adapt to the day row's width. From 22rem, the title and actions share the first row (title takes the remaining width and wraps, actions stay at the right) and the exercise count, duration and muscle badge slot fill the second row (5px vertical padding, about 64px tall with 32px fine-pointer actions); the badge slot takes the rest of that row and truncates rather than wrapping. From 52rem, a single grid row holds name, count, duration, badge slot and actions (about 48px). Below 22rem (very narrow screens, or enlarged text, since the thresholds are in rem) the card is a wrapping flex row and actions drop below only when they do not fit. From the 22rem container width, the metadata wrapper uses `display: contents` so its items join the card layout; below that it stays a wrapping flex wrapper. An empty weekday shows a dashed-border "Rest day" placeholder (44px minimum, 10px 12px padding, `.8125rem`) that remains a drop target. Opening the review never rearranges the days.

### Sliders
Native `<input type="range">` with no library (logging inputs are the documented exception: see Workout history and logger), in a `.slider` wrapper (`src/session-editor.js` builds them; limits come from `LIMITS` in `src/validate.js`).

- **Shape:** a 6px `--surface-2` track with a radius of 999px, like the volume bars, and an `--accent` fill from the start (or the min thumb) to the thumb. The visible knob is a 22px `--accent` circle with a 3px `--surface` ring, drawn as a radial gradient (`--knob`) inside a 44px-square thumb hit box. The wrapper is 44px tall, so a press anywhere within 22px of a knob's centre grabs it, two-thumb sliders included.
- **Alignment:** the track and fill are inset by half a thumb, and `--from` / `--to` (0–1, set by `setFill`) place the fill. Its ends always sit under the thumb's centre.

## Motion

- 150ms for colour/border changes on controls, 200–250ms for body map fills, bars and card highlights, `ease` timing; 200ms `ease-out` for card collapse/expand.
- New user-triggered disclosures reuse the existing 200ms `ease-out` grid-row/opacity pattern, with a matching chevron rotation. Animate both expansion and collapse so neighboring content moves smoothly. New overlays reuse the nearest existing tooltip/popover/dialog pattern; where none fits, default to a restrained 150ms `ease-out` opacity transition, with at most the existing 4px slide. Preserve feature-specific behavior and document intentional instant changes.
- Animate only the properties the interaction needs: colour/border, opacity, bar width, disclosure grid row/padding, or a restrained transform. Never use `transition: all`. Do not introduce decorative entrance sequences or animation libraries.
- Keep the same nodes alive through exit transitions and rapid reversals where practical; apply final hidden/removal state only after closing finishes. Closing/closed content must be noninteractive and hidden from assistive technology immediately, with focus moved to a logical visible control first. Cancel obsolete completion handlers so repeated toggles cannot hide reopened content. Reduced motion must reach the same final state without waiting for a transition event.
- Initial rendering, imports and routine refreshes show their final state without entrance motion unless a feature explicitly requires otherwise. Typing, slider readouts and same-subject data updates remain immediate. Preserve focus indicators without a delayed reveal.
- `prefers-reduced-motion: reduce` turns all transitions off.
